# План перехода на Web App + YooKassa + Marzban

## 1. Цель

Собрать новую архитектуру проекта, где:

- пользователь работает через красивый Telegram Mini App;
- покупка подписки идет через YooKassa;
- подтверждение оплаты приходит по webhook;
- срок подписки и доступ берутся с сервера;
- ключ/ссылка для подключения выдаются после оплаты;
- админ получает отдельную закрытую web-панель;
- админ управляет тарифами, аналитикой, YooKassa и серверами Marzban/VPS.

## 2. Что есть сейчас

- Оплата сейчас ручная, через модераторов.
- Тарифы захардкожены в backend.
- Веб-интерфейса нет.
- Админка есть только в Telegram-кнопках.
- VPN-выдача сейчас заглушечная: `access_url="mock://vpn"` и `config_blob="mock"`.
- Интеграции с Marzban пока нет.

## 3. Главное решение по структуре

Делаем отдельный заметный каталог:

- `webapp/` — весь frontend Mini App.

Внутри него:

- `webapp/user` или `webapp/src/pages/user` — личный кабинет пользователя;
- `webapp/admin` или `webapp/src/pages/admin` — админ-панель;
- `webapp/shared` — общие UI-компоненты, api-клиент, Telegram auth, графики.

Backend остается отдельным API-слоем и отдает:

- auth;
- тарифы;
- платежи;
- webhook YooKassa;
- подписки;
- данные Marzban;
- аналитику;
- админские настройки.

Критическое архитектурное правило:

- user web app никогда не ходит напрямую в VPS/Marzban;
- доступ к VPN-серверам есть только у backend;
- админ добавляет VPS/Marzban-серверы только через admin web app;
- backend сам выбирает сервер, создает/продлевает доступ и синхронизирует данные;
- пользователю backend отдает только готовые данные для ЛК: `ends_at`, `days_left`, ключ/`subscription_url`, статус доступа и кнопку `Продлить`.

## 3.1. Домен и `.env`

После покупки или подключения нового домена главным параметром проекта становится:

- `.env`
- `PUBLIC_BASE_URL=https://NEW_DOMAIN`

Именно `PUBLIC_BASE_URL` считаем главным публичным адресом проекта.

Что зависит от этого параметра:

- кнопка `👤 Профиль` в боте;
- кнопка `📊 Аналитика` в боте;
- user web app: `/webapp/user`;
- admin web app: `/webapp/admin`;
- `return_url` после оплаты YooKassa;
- публичный адрес backend API для web app;
- webhook URL YooKassa;
- адрес, который проксирует `nginx`/`Caddy`.

Что нужно сделать после появления нового домена:

1. Обновить `.env`: `PUBLIC_BASE_URL=https://NEW_DOMAIN`
2. Настроить DNS домена на IP VPS.
3. Настроить `nginx` или `Caddy` на этот домен.
4. Выпустить SSL (`Let's Encrypt`).
5. Перезапустить `backend` и `bot`.
6. Обновить webhook URL в кабинете YooKassa.

Важно:

- пока в `.env` стоит заглушка `PUBLIC_BASE_URL=https://vpn.example.com`, Telegram-кнопки web app не считаются боевыми;
- без реального публичного `HTTPS` домена user/admin Mini App из Telegram работать корректно не будут;
- для прод-режима после подключения домена dev-вход лучше отключить: `WEBAPP_DEV_AUTH_ENABLED=0`.

## 4. Пользовательский сценарий

### Если подписки нет

Показываем одну красивую центральную страницу:

- карточка продукта VPN;
- выбор периода: 1 месяц, 3 месяца, 6 месяцев, 12 месяцев;
- цена берется с сервера;
- итоговая сумма автоматически меняется после выбора периода;
- кнопка `Купить`;
- краткая инструкция, что будет после оплаты.

### После нажатия Купить

Сценарий:

1. frontend запрашивает у backend создание платежа;
2. backend создает платеж в YooKassa;
3. backend сохраняет локальный payment и `provider_payment_id`;
4. frontend получает `confirmation_url`;
5. пользователь уходит на оплату YooKassa;
6. пользователь оплачивает, например через СБП;
7. YooKassa отправляет webhook на наш backend;
8. backend подтверждает статус платежа, активирует подписку и запускает выдачу доступа;
9. frontend показывает loading/status screen;
10. после успешной оплаты пользователь возвращается в личный кабинет с активной подпиской.

Важно:

- backend не должен верить только редиректу пользователя;
- источник истины по оплате — webhook YooKassa + серверная проверка платежа.

## 5. Пользовательский личный кабинет после оплаты

Экран ЛК показывает:

- статус подписки;
- дату окончания подписки;
- сколько дней осталось;
- тип тарифа;
- сервер/локацию;
- ключ или ссылку подключения;
- кнопку копирования;
- краткую инструкцию по подключению.

Минимальный UX:

- по центру срок подписки;
- рядом или ниже `осталось N дней`;
- ниже поле с ключом;
- ниже иконка или кнопка копирования;
- ниже краткая инструкция по шагам;
- ниже кнопка `Продлить`.

Важно:

- срок, `days_left`, ключ и статус доступа приходят только с backend;
- frontend не вычисляет сам бизнес-логику продления и не обращается к Marzban напрямую;
- если доступ еще создается, backend отдает состояние `pending`, а ЛК показывает loading/status.

### Балансировка серверов

Нужен отдельный механизм server selection.

Что он делает:

- получает метрики с каждого Marzban-сервера;
- считает, какой сервер сейчас менее загружен;
- не отправляет новых пользователей на перегруженные узлы;
- умеет исключать сервер из ротации;
- умеет помечать сервер как `healthy`, `degraded`, `full`, `offline`.

Минимальные метрики для решения:

- количество активных пользователей;
- количество новых подключений за период;
- суммарный трафик за 1 час / 24 часа;
- доля заполнения по лимиту;
- доступность API;
- задержка ответа API;
- ручной вес сервера;
- флаг `enabled_for_new_users`.

Принцип выбора сервера:

1. исключить `offline` и отключенные серверы;
2. исключить серверы выше порога загрузки;
3. посчитать score;
4. выбрать сервер с лучшим score;
5. сохранить, почему был выбран именно он.

Пример score:

- меньше активных пользователей = лучше;
- меньше трафика за последний час = лучше;
- меньше заполнение лимита = лучше;
- выше ручной приоритет админа = лучше.

Нужен и фоновый пересчет:

- раз в час backend/worker опрашивает все серверы;
- обновляет агрегированные метрики;
- ставит статусы переполнения;
- пишет данные в аналитику.

## 13. Критические риски

## 14. Сетевая схема и Nginx

Используем `nginx`, но делим трафик на 2 типа:

- публичный пользовательский трафик;
- закрытый служебный трафик backend -> Marzban/VPS.

### Что должно быть публичным

Публично доступны:

- `backend/webapp` домен для Telegram Mini App;
- webhook endpoint YooKassa;
- VPN-inbound порты, через которые подключаются пользователи.

### Что не должно быть публичным для всех

Не открываем для всего интернета:

- API Marzban;
- web dashboard Marzban;
- служебные endpoints проверки состояния;
- внутренние admin endpoints на VPS.

### Как это делаем

На каждом VPS с Marzban:

- Marzban слушает локально или за `nginx`;
- `nginx` проксирует только API/dashboard трафик;
- firewall + `nginx allow/deny` разрешают доступ только с IP backend-сервера;
- все остальные запросы к Marzban API/dashboard блокируются.

На backend-сервере:

- `nginx` принимает публичный HTTPS;
- проксирует запросы к backend/webapp;
- backend ходит к VPS по защищенному адресу;
- credentials хранятся только на backend.

### Лучший вариант

Самый безопасный вариант:

- backend и VPS общаются не по публичным IP;
- использовать private network, WireGuard, Tailscale или cloud private network;
- `nginx`/firewall на VPS разрешают только private IP backend.

### Если private network нет

Минимально допустимый вариант:

- у backend есть статический публичный IP;
- на каждом VPS firewall разрешает доступ к Marzban API только с этого IP;
- `nginx` на VPS дополнительно делает `allow <backend_ip>; deny all;`.

### Важное разделение

Нельзя закрыть весь VPS "только для backend", потому что пользователи должны подключаться к VPN-узлам.

Поэтому закрываем только:

- Marzban API;
- Marzban dashboard;
- служебные порты.

А публичными остаются:

- Xray/VPN inbound порты для клиентов;
- домены/адреса, по которым подключается пользовательский клиент.

## 15. Итоговая целевая схема

### User flow

Telegram Bot -> User Mini App -> Выбор тарифа -> YooKassa -> Webhook -> Подписка активирована -> Marzban access created -> ЛК с ключом и сроком

### Admin flow

Telegram Bot -> Admin Mini App -> Dashboard / Тарифы / YooKassa / Инструкции / Серверы / Аналитика

## 16. Что делать первым

Первый правильный рабочий спринт:

1. создать `webapp/`;
2. внедрить Telegram auth для webapp;
3. вынести тарифы из кода в БД;
4. подключить YooKassa create payment + webhook;
5. сделать user-страницу без подписки и user-страницу с подпиской;
6. добавить admin-страницу тарифов и YooKassa settings;
7. только потом подключать Marzban и расширенную аналитику.
